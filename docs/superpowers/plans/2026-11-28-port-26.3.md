# Port auf Minecraft 26.3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stash-Hunter baut und läuft gegen Minecraft 26.3 / Meteor 26.3, ohne Verhaltensänderung.

**Architecture:** Versions-Pins anheben, API-Brüche an der kleinsten Stelle beheben, Doku nachziehen. Keine neuen Funktionen.

**Tech Stack:** Gradle (Kotlin DSL), Fabric Loom, Java 25, Meteor Client 26.3-SNAPSHOT, Baritone 26.3-SNAPSHOT (compileOnly), Xaero's Minimap (compileOnly), JUnit, Spotless.

**Spec:** `docs/superpowers/specs/2026-11-28-port-26.3-design.md`

## Global Constraints

- Branch `port/26.3`; der Port ist von späteren Funktionen getrennt committet.
- `minecraft_version=26.3`, `baritone_version=26.3-SNAPSHOT`, `xaero_minimap_version=fabric-26.3-26.6.2` (Modrinth, geprüft 2026-11-28).
- `fabric-resource-loader-v1` = `3.0.4+ba0d6c0d5d` (die Version, die fabric-api `0.162.0+26.3` und damit Meteor 26.3 bündelt, geprüft 2026-11-28).
- `loader_version` bleibt `0.20.1` (Meteor 26.3 verlangt `0.19.5`, neuer ist erlaubt).
- `fabric.mod.json`: `meteor-client` und `baritone-meteor` auf `~26.3-`.
- `mod_version=26.3.0-dev` bis zum Release.
- Loom nur anheben, wenn 1.17.21 26.3 nicht baut. Dann die neueste `1.18.x`-Release (Meteor 26.3 nutzt 1.18), und im Build-Script-Kommentar und README vermerken, dass Gradle dann selbst auf JDK 25 laufen muss.
- Verhalten unverändert gegenüber 26.2.2. Alle bestehenden Unit-Tests bleiben grün (Stand 26.2.2: 157 in 28 Suites).
- Build-Befehl: `./gradlew clean build` (Windows `gradlew.bat clean build`) mit JDK 25.

## Review Focus

- **Baritone nicht installiert:** Mod startet und fliegt mit dem eingebauten Regler. Alle Baritone-Aufrufe bleiben hinter `BaritoneBridge`/`FabricLoader.isModLoaded("baritone-meteor")`. Prüfen per Grep in Task 1, Schritt 5.
- **Xaero nicht installiert:** keine `NoClassDefFoundError`. Gleiche Grep-Prüfung für `XaeroBridge`.
- **Bestehende Config- und Trip-Dateien aus 26.2.2** laden ohne Fehler. Die Serialisierungs-Tests (`TripSerializationTest`, `ChestIndexTest`, `ReportedStashesTest`) laufen unverändert grün.
- **Umbenannte Meteor-Events oder -Utilities** (z. B. `GameLeftEvent`, `BlockUpdateEvent`, `InvUtils`): Ersatz mit gleicher Semantik, nicht nur so, dass es kompiliert. Jede solche Ersetzung steht in der Commit-Nachricht.
- **`${mc_version}`-Expansion in `fabric.mod.json`:** Das gebaute Jar enthält `"minecraft": "26.3"`. Prüfen in Task 1, Schritt 6.

### Task 1: Versionen anheben und kompilierbar machen

**Files:**
- Modify: `gradle.properties` (Zeilen `minecraft_version`, `mod_version`, `baritone_version`, `xaero_minimap_version`)
- Modify: `build.gradle.kts` (`compileOnly("net.fabricmc.fabric-api:fabric-resource-loader-v1:…")`; Loom-Version nur bei Bedarf)
- Modify: `src/main/resources/fabric.mod.json` (`depends.meteor-client`, `recommends.baritone-meteor`)
- Modify: alle Java-Dateien unter `src/main/java/com/stashhunter/stashhunter/`, die gegen 26.3 nicht kompilieren
- Test: bestehende Suites unter `src/test/java/com/stashhunter/stashhunter/utils/`

**Interfaces:**
- Consumes: nichts
- Produces: ein auf 26.3 grüner Build, auf dem alle späteren Pläne aufsetzen. Öffentliche Klassen- und Methodennamen der Mod bleiben unverändert.

- [ ] **Step 1: Pins setzen**

Werte aus „Global Constraints“ in `gradle.properties`, `build.gradle.kts` und `fabric.mod.json` eintragen. Den Kommentar zu `fabric-resource-loader-v1` in `build.gradle.kts` auf „26.3 / fabric-api 0.162.0+26.3“ anpassen.

- [ ] **Step 2: Abhängigkeiten auflösen**

Run: `./gradlew --refresh-dependencies dependencies --configuration compileClasspath`
Expected: `BUILD SUCCESSFUL`. `meteor-client:26.3-SNAPSHOT`, `baritone:26.3-SNAPSHOT`, `xaeros-minimap:fabric-26.3-26.6.2` werden aufgelöst. Scheitert Loom an der Minecraft-Version, die Loom-Regel aus „Global Constraints“ anwenden und wiederholen.

- [ ] **Step 3: Kompilieren und Fehlerliste festhalten**

Run: `./gradlew compileJava`
Expected beim ersten Lauf: Compile-Fehler durch API-Änderungen (oder keine). Liste als Arbeitsliste nutzen.

- [ ] **Step 4: Compile-Fehler beheben**

Jeden Fehler an der kleinsten Stelle beheben: umbenannte Klassen/Methoden in Minecraft, Meteor oder Baritone durch die 26.3-Entsprechung mit gleicher Semantik ersetzen. Kein Umbau, keine Verhaltensänderung. Bei unklarer Semantik den Vanilla- bzw. Meteor-Quelltext von 26.3 lesen, nicht raten.

- [ ] **Step 5: Soft-Dependencies prüfen**

Run: `git grep -n "baritone\.\|xaero\." -- src/main/java ':!src/main/java/com/stashhunter/stashhunter/baritone' ':!src/main/java/com/stashhunter/stashhunter/xaero'`
Expected: keine Treffer auf Baritone-/Xaero-Klassen außerhalb der Bridge-Pakete (Imports von `com.stashhunter.stashhunter.baritone.BaritoneBridge` bzw. `…xaero.XaeroBridge` sind erlaubt).

- [ ] **Step 6: Vollständiger Build**

Run: `./gradlew clean build`
Expected: `BUILD SUCCESSFUL`, Spotless sauber, alle Tests grün (mindestens 157), Jar `build/libs/stash-hunter-26.3.0-dev.jar`. Danach `unzip -p build/libs/stash-hunter-26.3.0-dev.jar fabric.mod.json` zeigt `"minecraft": "26.3"` und `"meteor-client": "~26.3-"`.

- [ ] **Step 7: Commit**

```bash
git add gradle.properties build.gradle.kts src/main/resources/fabric.mod.json src/main/java
git commit -m "Port to Minecraft 26.3"
```
Commit-Nachricht: Liste der API-Ersetzungen aus Step 4 im Body.
