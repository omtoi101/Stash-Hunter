# Port auf Minecraft 26.3 — Design (kurz)

**Stand:** 2026-11-28, abgesegnet. Erste Etappe des Releases 26.3.0. Danach folgen auf demselben
Branch, mit jeweils eigenem Design: Erkennung, Struktur-Locator, Auswertung, Flug & Komfort.

## Warum

Minecraft 26.3 ist erschienen. Stash-Hunter ist hart auf 26.2 gepinnt und lädt dort nicht. Alle
weiteren Arbeiten und der noch ausstehende In-game-Test sollen direkt auf 26.3 stattfinden.

## Ziele

- Stash-Hunter baut gegen Minecraft 26.3 und läuft dort mit Meteor 26.3.
- `gradlew build` grün: Compile, Spotless, alle Unit-Tests (Stand 26.2.2: 157 in 28 Suites).
- Verhalten unverändert gegenüber 26.2.2.

## Nicht-Ziele

- Keine neuen Funktionen, kein Umbau. Die kommen in den folgenden Etappen.
- Keine Unterstützung für 26.2 im selben Jar. Wer 26.2 spielt, bleibt bei 26.2.2.
- Kein eigenes Release für den Port. Die Version 26.3.0 wird erst nach allen Etappen veröffentlicht.

## Ansätze

| Ansatz | Bewertung |
|---|---|
| **Nur 26.3, Pins anheben** (gewählt) | Wenig Aufwand, gleiches Modell wie Meteor und das meteor-addon-template. |
| Ein Jar für 26.2 und 26.3 | Bräuchte Versionsweichen oder Multi-Projekt-Build; Meteor selbst unterstützt pro Build nur eine Version. Verworfen. |
| Remote-Branch `origin/26.3` weiterführen | Enthält nur Gradle-Wrapper-/CI-Bumps, Minecraft bleibt 26.2. Bringt nichts. Verworfen. |

## Umsetzung

- Branch `port/26.3` von `main`. Der Port ist ein eigener Commit (oder eine kleine Commit-Folge),
  getrennt von späteren Funktionen.
- `gradle.properties`: `minecraft_version=26.3`, `baritone_version=26.3-SNAPSHOT`,
  `xaero_minimap_version=fabric-26.3-…` (aktuelle Version von Modrinth), `loader_version` auf den
  Stand, den Meteor 26.3 verlangt. Meteor folgt automatisch (`${minecraft_version}-SNAPSHOT`).
  Verfügbarkeit geprüft am 2026-11-28: `meteor-client 26.3-SNAPSHOT` und `baritone 26.3-SNAPSHOT`
  liegen auf maven.meteordev.org/snapshots.
- `build.gradle.kts`: `fabric-resource-loader-v1` auf die Version, die Meteor 26.3 bündelt.
  Loom nur anheben, wenn 26.3 es erzwingt (Hinweis im Build-Script zu JDK/Gradle beachten).
- `fabric.mod.json`: `meteor-client` und `baritone-meteor` auf `~26.3-`.
- Compile-Fehler durch API-Änderungen in Minecraft/Meteor/Baritone 26.3 beheben, an der
  kleinstmöglichen Stelle und ohne Verhaltensänderung.
- README (Anforderungen, „Built for“), CHANGELOG (neuer Abschnitt `[Unreleased]`, Eintrag unter
  *Changed*/*Development*) und PLAN.md (Abschnitt „Port auf MC 26.3/26.4“ als erledigt) anpassen.
- `mod_version` bleibt bis zum Release auf einem Vorab-Stand (Vorschlag `26.3.0-dev`), 26.3.0 erst
  beim Release.

## Dem Umsetzenden überlassen

- Genaue Versionen von Loader, Xaero und `fabric-resource-loader-v1` (aus Meteors Jar-Liste bzw.
  Modrinth).
- Wie API-Brüche im Einzelnen gelöst werden, solange das Verhalten gleich bleibt.
